Project overview

ctx searches the coding-agent history already on your machine.

It imports local transcripts from tools such as OpenCode, Claude Code, Codex, Cursor, Gemini, Copilot CLI, and other supported sources into a local SQLite index, then exposes search, transcript lookup, read-only SQL, docs, and MCP tools.

Core concepts

Local-first index

ctx setup creates local storage and indexes discovered history. ctx import can refresh all sources, one provider, one path, or a custom ctx-history-jsonl-v1 file.

No hosted service

This fork removed telemetry, self-update, hosted endpoints, analytics, and network calls. Release updates come from SourceHut tags and Nix/download artifacts.

Sessions and events

Search results point at ctx-owned session and event IDs. Use ctx show session or ctx show event to recover the original transcript context.

Provider adapters

Built-in adapters read local files/databases for Codex, Pi, Claude Code, OpenCode, OpenClaw, Hermes, NanoClaw, AstrBot, Antigravity, Gemini CLI, Cursor CLI, Copilot CLI, and Factory AI Droid where those histories exist.

Main workflows

01 Discover and index

Start with setup, then inspect what ctx found.

ctx setup
ctx status
ctx sources

02 Search past work

Search defaults to diverse session-level results and can be scoped by provider, workspace, event type, file, time window, or session.

ctx search "failed migration"
ctx search "token budget" --limit 5
ctx search "review findings" --include-subagents

03 Recover context

Open a whole transcript or one event window from a search result.

ctx show session <ctx-session-id>
ctx show event <ctx-event-id> --window 10

04 Give agents memory

Serve the same read-only local index to compatible agents over MCP, or query it directly with read-only SQL.

ctx mcp
ctx sql "SELECT provider, COUNT(*) FROM ctx_sessions GROUP BY provider"
